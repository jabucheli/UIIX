# INSTRUCCIONES PARA DESARROLLAR LA PRESENTACIÓN WEB DE TESIS DOCTORAL

## 1. OBJETIVO GENERAL

Desarrollar una **presentación académica interactiva en formato página web**, destinada a la sustentación de una tesis doctoral.

La presentación debe comportarse visualmente como una presentación PowerPoint, pero implementada dentro de una página web.

### Regla principal de navegación

- Cada **pestaña principal de la página web debe representar una sola diapositiva**.
- No se debe presentar contenido continuo tipo documento o página de lectura vertical.
- Al cambiar de pestaña, se debe mostrar únicamente la diapositiva correspondiente.
- La relación debe ser:
  - Pestaña 1 = Diapositiva 1
  - Pestaña 2 = Diapositiva 2
  - Pestaña 3 = Diapositiva 3
  - etc.
- La interfaz debe permitir agregar nuevas diapositivas posteriormente sin rediseñar toda la aplicación.

---

# 2. TÍTULO OFICIAL DE LA TESIS

Utilizar exactamente el siguiente título:

**“Estrategia metodológica de gestión de proyectos basada en controles de ingeniería, orientada a la mejora de las condiciones de seguridad laboral y la prevención de riesgos en proyectos de construcción de la ciudad de Quito, en conformidad con la normativa ecuatoriana vigente entre 2024 y 2026”**

No resumir, modificar ni reinterpretar el título en la carátula.

# 4. ESTRUCTURA GENERAL DE LA PÁGINA WEB

La aplicación debe tener una estructura similar a un visor de presentación.

## Encabezado superior

Crear una barra superior discreta que permita identificar la presentación.

Puede contener:

- título corto de la tesis;
- indicador del número de diapositiva;
- controles de navegación;
- botón para pantalla completa.

Evitar que el encabezado compita visualmente con la diapositiva.

---

# 5. SISTEMA DE PESTAÑAS

Crear una fila o panel de pestañas.

Inicialmente deben existir como mínimo:

- **Diapositiva 1 – Carátula**
- **Diapositiva 2 – Problematización**

Las pestañas deben ser escalables para incorporar después las siguientes diapositivas de la tesis.

Ejemplo conceptual:

`[ 1. Carátula ] [ 2. Problematización ] [ 3. ... ] [ 4. ... ]`

También pueden incorporarse botones:

`Anterior` | `Siguiente`

---

# 6. FORMATO VISUAL DE CADA DIAPOSITIVA

Cada diapositiva debe mostrarse dentro de un contenedor con proporción aproximada **16:9**, equivalente a una presentación PowerPoint panorámica.

La diapositiva debe:

- ocupar la mayor parte de la pantalla;
- permanecer centrada;
- conservar su proporción al cambiar el tamaño de la ventana;
- evitar scroll vertical dentro de la diapositiva;
- mantener todos los elementos visibles simultáneamente;
- permitir visualización adecuada en pantalla completa;
- mantener una apariencia profesional de sustentación doctoral.

La prioridad es que la pantalla se perciba como una **diapositiva**, no como una página web convencional.

La carátula debe quedar preparada para incorporar posteriormente:

- nombre del doctorando;
- universidad;
- programa doctoral;
- director o tutor;

- logotipos institucionales.

Si estos datos no se encuentran disponibles, no inventarlos.

## “Diapositiva 2 – Problematización”

Todo su contenido debe caber dentro de **UNA SOLA DIAPOSITIVA**.

# 9. FUENTE DE INFORMACIÓN DE LA PROBLEMATIZACIÓN

Leer y analizar:

`d:\ia\tes\probl.docx`

A partir del documento identificar solamente la información más relevante para explicar visualmente:

1. contexto general;

3. causas principales;

5. consecuencias;

7. efectos sobre la prevención de riesgos;

9. limitaciones relacionadas con controles de ingeniería;
10. relación con proyectos de construcción de Quito;
11. relación con la normativa ecuatoriana vigente;

Deben utilizarse únicamente aquellas que realmente estén sustentadas en `probl.docx`.

---

# 10. PRINCIPIO DE SÍNTESIS

La diapositiva no debe convertirse en una página llena de párrafos.

Aplicar el siguiente criterio:

**Mucho contenido conceptual → poco texto → alta representación visual.**

Priorizar:

- palabras clave;
- conceptos breves;
- cifras relevantes;
- relaciones causales;
- conexiones;
- jerarquías;
- flechas;
- íconos;
- bloques gráficos;
- nodos;
- diagramas.

Evitar párrafos extensos.

---

# 11. ESTRUCTURA GRÁFICA PROPUESTA PARA LA DIAPOSITIVA 2

Organizar la diapositiva en dos grandes zonas.

## ZONA A – PROBLEMATIZACIÓN

Ubicación:

**aproximadamente 70–75 % del ancho de la diapositiva, desde el borde izquierdo hacia el centro.**

Utilizar una representación gráfica combinada.

Se puede seleccionar, según lo que mejor represente `probl.docx`:

- flujograma;
- mapa mental;
- secuencia gráfica;
- diagrama causa–problema–efecto;
- esquema jerárquico;
- combinación de estas técnicas.

No utilizar una tabla tradicional como recurso principal.

---

# 12. SECUENCIA VISUAL RECOMENDADA

Cuando el contenido de `probl.docx` lo permita, estructurar visualmente la problematización mediante la siguiente secuencia:

**CONTEXTO**

↓

**FACTORES / CAUSAS**

↓

**PROBLEMA CENTRAL**

↓

**CONSECUENCIAS**

↓

**BRECHA IDENTIFICADA**

↓

**NECESIDAD DE UNA ESTRATEGIA METODOLÓGICA BASADA EN CONTROLES DE INGENIERÍA**

Esta estructura no debe asumirse automáticamente.

Primero analizar `probl.docx` y adaptar los conceptos reales del documento a esta secuencia.

---

# 13. PROBLEMA CENTRAL

El problema central debe ser el elemento visual de mayor jerarquía dentro del diagrama.

Debe:

- estar claramente diferenciado;
- ubicarse aproximadamente en el centro de la zona gráfica;
- sintetizar el problema investigado;
- basarse estrictamente en `probl.docx`;
- relacionar, cuando el documento lo permita:
  - gestión de proyectos;
  - seguridad laboral;
  - prevención de riesgos;
  - controles de ingeniería;
  - construcción;
  - ciudad de Quito.

No redactar un nuevo problema de investigación si el documento ya contiene una formulación específica.

---

# 14. REPRESENTACIÓN DE LAS CAUSAS

Ubicar las causas o factores antecedentes visualmente antes del problema central.

Pueden utilizarse entre **3 y 6 nodos principales**, siempre que estén sustentados por `probl.docx`.

Ejemplo únicamente de estructura visual:

`Causa 1`  
`Causa 2` → **PROBLEMA CENTRAL**  
`Causa 3`  
`Causa 4`

No utilizar estos textos como contenido definitivo.

Extraer los términos reales del documento.

---

# 15. REPRESENTACIÓN DE LAS CONSECUENCIAS

Desde el problema central deben desprenderse las principales consecuencias encontradas en `probl.docx`.

Priorizar consecuencias relacionadas con:

- condiciones de seguridad laboral;
- exposición a riesgos;
- accidentes;
- gestión preventiva;
- desempeño del proyecto;
- controles implementados;
- cumplimiento normativo;

pero únicamente cuando estas ideas se encuentren sustentadas en el documento.

---

# 16. BRECHA DE INVESTIGACIÓN

La secuencia gráfica debe permitir entender visualmente que existe una **brecha o necesidad no resuelta**.

La brecha debe conducir conceptualmente hacia la necesidad de la tesis:

**desarrollar una estrategia metodológica de gestión de proyectos basada en controles de ingeniería.**

No convertir la diapositiva en la exposición completa de la propuesta.

En esta etapa solamente debe mostrarse que la problematización **conduce lógicamente a la necesidad de la investigación**.

---

# 17. ZONA B – JUSTIFICACIÓN

Reservar aproximadamente **25–30 % del ancho de la diapositiva, en el lado derecho**, para mostrar los tipos de justificación mencionados en:

`d:\ia\tes\probl.docx`

Crear un bloque visual independiente titulado:

## JUSTIFICACIÓN

Debajo deben aparecer los **tipos de justificación realmente identificados en el documento**.

Ejemplos posibles de categorías académicas podrían ser:

- justificación teórica;
- justificación metodológica;
- justificación práctica;
- justificación social;
- justificación normativa;
- justificación técnica;

pero estos ejemplos **NO deben incorporarse automáticamente**.

### Regla obligatoria

Leer `probl.docx` y mostrar solamente las categorías de justificación que el documento mencione o desarrolle explícitamente.

No inventar categorías.

---

# 18. PRESENTACIÓN GRÁFICA DE LAS JUSTIFICACIONES

Cada tipo de justificación debe mostrarse como una tarjeta o bloque compacto.

Cada tarjeta puede contener:

**Tipo de justificación**

+

una frase muy breve, de aproximadamente **5 a 15 palabras**, que explique su aporte.

Ejemplo conceptual:

`[ ICONO ]`

**JUSTIFICACIÓN ______**

Frase breve tomada o sintetizada fielmente desde `probl.docx`.

Utilizar preferentemente:

- iconografía académica;
- símbolos técnicos;
- pequeños conectores;
- bloques con bordes;
- destacados visuales.

No usar párrafos largos.

---

# 19. RELACIÓN ENTRE PROBLEMATIZACIÓN Y JUSTIFICACIÓN

La composición debe permitir que el usuario comprenda que:

**la problemática identificada genera la necesidad de realizar la investigación y fundamenta su justificación.**

Visualmente puede utilizarse:

- una línea;
- una flecha;
- una transición;
- un cambio de color;
- un conector gráfico;

entre la zona de problematización y la zona de justificación.

---

# 20. JERARQUÍA VISUAL

Aplicar aproximadamente la siguiente jerarquía:

### Nivel 1

**PROBLEMATIZACIÓN**

Título principal.

### Nivel 2

**Problema central**

Elemento visual más destacado del cuerpo.

### Nivel 3

Causas, consecuencias, contexto y brecha.

### Nivel 4

### Zona lateral

**JUSTIFICACIÓN**

Con tarjetas diferenciadas.

# 23. TIPOGRAFÍA

2. mantener proporciones semejantes;

Máximo recomendado:

- una familia tipográfica;
- máximo dos pesos principales;
- un peso especial para títulos.

# 25. FOTOGRAFÍAS

Si `ejemplo.pptx` utiliza fotografías como parte importante de su lenguaje visual, se puede incorporar una imagen relacionada con construcción o seguridad laboral.

- no debe ocupar demasiado espacio;
- no debe contener marcas de agua;
- debe mantener buena resolución;
- debe integrarse al diseño.

La información conceptual siempre tiene prioridad sobre la decoración.

---

# 26. ANIMACIONES

La versión inicial no necesita animaciones complejas.

Si posteriormente se incorporan animaciones, deben ser discretas.

Posible secuencia:

1. aparece el contexto;
2. aparecen las causas;
3. aparece el problema central;
4. aparecen las consecuencias;
5. aparece la brecha;
6. aparecen las justificaciones.

No utilizar animaciones llamativas, rebotes o efectos incompatibles con una defensa doctoral.

# 29. ESTRUCTURA TÉCNICA RECOMENDADA

Construir la aplicación de forma modular.

Ejemplo conceptual:

```text
/app
  /components
      SlideContainer
      SlideTabs
      SlideNavigation
      FlowDiagram
      JustificationCard

  /slides
      Slide01Cover
      Slide02Problematization

  /data
      thesisData
      problematizationData

  /assets
      icons
      images
      logos
```

La información de cada diapositiva debe estar separada de la estructura general de navegación.

Esto permitirá agregar posteriormente las diapositivas 3, 4, 5, etc.

---

# 30. MODELO DE DATOS DE LAS DIAPOSITIVAS

Manejar conceptualmente las diapositivas mediante una estructura similar a:

```javascript
slides = [
  {
    id: 1,
    title: "Carátula",
    component: Slide01Cover
  },
  {
    id: 2,
    title: "Problematización",
    component: Slide02Problematization
  }
]
```

De esta forma la presentación podrá crecer sin modificar el sistema de navegación.

# 34. CRITERIO DE PRESENTACIÓN DOCTORAL

La diapositiva debe servir como **apoyo visual al discurso del expositor**, no como sustituto del discurso.

Por esta razón:

- evitar copiar páginas completas de la tesis;
- evitar párrafos;
- evitar definiciones largas;
- evitar exceso de citas;
- destacar relaciones conceptuales;
- mostrar únicamente aquello que el expositor necesita reforzar visualmente.

La meta es que el tribunal comprenda rápidamente:

**qué problema existe → qué lo origina → qué consecuencias genera → qué brecha permanece → por qué la investigación es necesaria.**
